# Koleex AI — clean-up and deep check (2026-09-11)

Owner's ask: "clean and organize the Koleex AI app, fix any problem, debug, deep-check UI/UX, and tell me what needs improving so I can decide."

Method: five independent read-only reviews over `src/components/ai`, `src/lib/voice`, `src/lib/server/ai*`, `src/app/api/ai/**`, `src/app/ai`, the docs and the validators (chat client, voice client, server security, UI/UX, repository hygiene), then every top finding verified against the code before anything was changed. Baseline `e613b38`.

Overall: no P0 on the server. Auth, the confirm ledger, attachment fencing, the picture proxy's SSRF guard and voice key handling hold as the validators claim. The defects clustered in (a) the knowledge routes, built before the AI hardening passes, (b) the legacy provider stack behind three side routes, (c) error branches of the chat client, (d) voice-call release paths, and (e) English literals inside Arabic/Chinese screens.

### Product / UX (from the UI/UX review)
1. **One voice entry.** Merge the dictation mic into the call control (or long-press) so the composer has one "Speak"; give the in-call voice picker its own glyph; settle End (red X) vs Close (grey X) with a distinct handset glyph or an Undo toast. *M*
2. **Token pass for the AI app.** One blue (`#0066FF`) instead of three, brand functional colours, a 4-step radius scale and a 12/13/14/16/18 type ladder across `components/ai`. *M*
3. **44 px touch-target pass** on the composer row, sidebar rows/pin/menu, bubble action row and the "Latest" chip; 16 px inputs so pinch-zoom can be re-enabled (`userScalable: false` today). *M*
4. **Contrast pass.** Raise `--text-dim` (≈4.4:1) and the call screen's `#666666` captions (≈3.4:1) to AA; floor informational labels at 12 px. *S, visible change*
5. **URL-backed navigation** (`?c=<id>`, `?view=library|calls`) so Back works inside the PWA and chats are linkable. *M*
6. **Connection layer.** Online/offline banner, Speak disabled offline, queued resend, a proper "failed to load" card instead of the greeting on a failed chat load. *M*
7. **Voice caption redesign + Arabic register pass** (formal MSA and Egyptian colloquial are mixed on one screen). *M*
8. **Call settings sheet**: title it "Call settings" and either wire swipe-down or drop the drawn handle. *S*
9. **Focus management** for the call dialog, voice sheet, project dialog, lightbox, mobile drawer and row menus (move focus in, trap Tab, restore on close). *M*
10. **Bigger accessibility items**: nested buttons in `role="button"` sidebar rows; hidden-but-focusable collapsed sidebar (`inert`). *M*

### Engineering
11. **Retire or support two dead-but-published routes**: `/api/ai/chat` and `/api/ai/conversations/[id]/messages` have no in-repo caller and survive only via `/api/v1/ai/*`. Retire with a 410 on the v1 path, or keep and finish hardening. Behind them sit two more provider stacks (`ai-provider.ts`, `providers/*`) that duplicate the hardened `core/transport` path — collapse once the routes are decided. *M/L*
12. **Four unauthenticated lab pages in production**: `/ai-orb-lab`, `/ai-face-lab`, `/ai/orb-demo`, `/orb-lab` (no nav link, no auth, no `noindex`). Gate behind `AdminAuth` or return 404 in production; `ai-face-lab` + `KoleexRobot.tsx` (477 lines) look abandoned; `orb-demo`/`orb-lab` duplicate each other. *S*
13. **Tool-argument validation is log-only by default** (`AI_TOOL_VALIDATION=enforce` flips it). Approved by the owner; NOT flipped yet — the observation it depends on could not be made: the platform log query for `[ai.tool.validate]` lines timed out on every window wider than four hours, and the four-hour windows that did answer held no lines at all (no issues, or no tool calls — indistinguishable). Next step: set `AI_TOOL_VALIDATION=enforce` on the Preview environment first, exercise the tools there, then flip the default in code. *S*
14. **Provider error bodies logged verbatim** (can echo the user's prompt) in `providers/*`, `ai-provider.ts`, orchestrator, vision. Log status + classified reason; bodies behind `AI_DEBUG_REPLIES`. *S*
15. **Live-turn content has no route-level cap** on `/api/ai/agent` (history 48k, attachments 60k, the turn itself unbounded). Pick a ceiling. *S*
16. **Unify the error envelope** across the 31 routes (`{error}`, `{error,message}`, `{fallback,reason}`…), and stop returning Postgres/transport text on 500s. *M*
17. **DNS-rebinding window** in `assertSafeUrl` (resolve-then-fetch-by-name). Accept as residual or pin the connection to the vetted IP. *M*
18. **Decompose** `send()` (~570 lines, three copies of the sidebar-bump reducer) and `startCall`/`connect`/`dialWs` (200–300 lines each) along the seams already marked in comments; add a `recoveryPlan()` owner for the four retry layers. *L*
19. **Performance**: memoise `Bubble` props (inline lambdas defeat `memo`), stop meter ticks re-rendering the whole call screen (`React.memo(VoiceTranscript)`, CSS-variable path for the orb level), lazy-load `VoiceCallButton`. *M*
20. **Validators run only by hand** (42 scripts, none in CI). Add an aggregate `validate:ai` and a workflow. *S*
21. **Mainland worst case**: the connecting chain can exceed two minutes (ws 15 s → rtc 50 s → grace → alt 50 s); cap total connecting time (~45 s) and say so honestly. The lane probe can also override a caller's explicit line choice on the next load — mark user-chosen lanes as such. *M*
